**Why `ListBucket`, when nothing lists.** Without it S3 answers a key that does
not exist with **403 AccessDenied**, not NoSuchKey. `S3Service.getObject`
catches only `NoSuchKeyException`, so a row pointing at a missing object would
be a 500 in production and a 404 everywhere else — MinIO's root credentials can
always list. Arpan chose the grant over mapping 403 to 404 in code, which would
also have disguised a real permission fault as *not found*.

## 2. Remove the unused CORS rule — Arpan · console

**Why.** Browsers never talk to the bucket: uploads and reads both go through
the API ([ADR-010](../decisions/ADR-010-uploads-stream-through-the-api.md),
[ADR-007](../decisions/ADR-007-uploaded-media-is-streamed-by-the-api.md)). The
rule is the shape a presigned-upload flow needs, and that flow was decided
against, so it grants a capability nothing uses.

- [x] **S3 → `campusvibe-prod-media` → Permissions → Cross-origin resource
  sharing (CORS) → Edit** → empty the editor → **Save changes**. **Done
  2026-09-12** with `aws s3api delete-bucket-cors`, run by Arpan — the guard
  hook refuses every `delete-*`, bucket configuration included.

**Verify:**
```bash
aws s3api get-bucket-cors --bucket campusvibe-prod-media   # NoSuchCORSConfiguration
```

## 3. One policy, not two — Arpan · console

- [ ] **IAM → Policies → `CampusVibeProdMediaS3Access`** duplicates the inline
  grant and is attached to nothing. Delete it — or attach it and remove the
  inline policy — but keep exactly one.

## 4. Versioning — optional, decide later

Today an overwritten or deleted object is gone. Overwrites are unlikely, since
every key is a fresh uuid, but deletes are real: a replaced logo's old object is
removed on purpose. Versioning with a lifecycle rule that expires noncurrent
versions after some days would make a mistaken delete recoverable, at the cost
of storing the old bytes that long. Nothing needs it to connect.

## 5. Verify the first upload — Check

After [`connecting-elastic-beanstalk.md`](connecting-elastic-beanstalk.md) §5
and the first administrator:

- [ ] Log in as the administrator in the deployed frontend, create a test club,
  and upload a logo from its page. Or with `curl`, using a token from the login
  response's `Authorization` header — never paste a real password into a file:
  ```bash
  API=https://api.campusvibe-mcgill.com
  curl -s -X POST $API/api/v1/clubs/<club-id>/logo \
    -H "Authorization: Bearer $TOKEN" -F 'file=@logo.png;type=image/png'
  ```
- [ ] The logo comes back as an image:
  ```bash
  curl -sI $API/api/v1/clubs/<club-id>/logo | grep -iE '^HTTP|content-type|x-content-type-options'
  ```
- [ ] The object is in the bucket under the club's prefix:
  ```bash
  aws s3api list-objects-v2 --bucket campusvibe-prod-media --prefix clubs/ \
    --query 'Contents[].Key'                  # clubs/<club-id>/logos/<uuid>.png
  ```
- [ ] **A logo between 1 MB and 5 MB uploads** — a 3 MB file returns 200, not
  nginx's HTML 413. Proves the `deploy/eb/.platform/` body limit, which no local
  test can reach
- [ ] **An event photo renders** — once the event photo unit has shipped: upload
  through `POST /api/v1/events/<event-id>/images`, then open the event page
  through Vercel; the object lists under `events/<event-id>/images/`
- [ ] **A missing object is a 404, not a 500** — the `ListBucket` grant working
- [ ] **This closes [BUG-051](../../bugs/bugs.md#bug-051)** — move it at the next wrap-up.

Deleting the test club afterwards leaves its object behind (see below);
deleting an object is Arpan's.
