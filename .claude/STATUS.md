## Watch out

- `Club.id` is an assigned slug, so `save` merges and hands back a *different* instance — two bugs in one method ([BUG-034](bugs/fixed_bugs.md#bug-034), [BUG-037](bugs/fixed_bugs.md#bug-037)); held by [`rules/backend-clubs.md`](rules/backend-clubs.md), fix proposed in [ADR-002](docs/decisions/ADR-002-club-id-is-an-assigned-slug.md).
- Never accept Copilot Autofix on CodeQL alerts 14/15 — returning a copy of an entity collection loses every upload ([BUG-022](bugs/fixed_bugs.md#bug-022), [BUG-023](bugs/fixed_bugs.md#bug-023)); [`rules/backend-java.md`](rules/backend-java.md).
- **`ClubService.create` no longer exists** — `createOwnedBy` is the only way to make a club, and a null owner means born ownerless, which only the dev seeder may pass ([ADR-004](docs/decisions/ADR-004-two-paths-create-a-club.md)); [`rules/backend-clubs.md`](rules/backend-clubs.md).
- **A stored S3 key is not a URL, and `next/image` throws on one *during render*** — no `onError` can catch it, so one bad row takes a whole page down ([BUG-040](bugs/fixed_bugs.md#bug-040)); [`rules/frontend.md`](rules/frontend.md).
- **The store no longer guards the key, so the code must.** MinIO, like S3, reads `..` in a key as two characters; the filesystem stub that stood in for S3 until 2026-09-12 turned it into a file write, which was [BUG-039](bugs/fixed_bugs.md#bug-039). `MediaKeys.assertSafeKey`, applied in `S3Service`, is now the only check — do not remove it because the store does not need it ([ADR-011](docs/decisions/ADR-011-minio-replaces-fakes3.md)); [`rules/backend-java.md`](rules/backend-java.md).
- **Every Spring context needs `aws.s3.bucket`.** No default, and a blank value is rejected — so a test class that skips the `test` profile must name it, as `SearchIT` and `SearchRateLimitIT` now do, and an environment that forgets `AWS_S3_BUCKET` refuses to boot ([BUG-051](bugs/bugs.md#bug-051), [ADR-012](docs/decisions/ADR-012-one-media-bucket-with-prefixes.md)); [`rules/backend-java.md`](rules/backend-java.md), [`rules/aws-handling.md`](rules/aws-handling.md).
- **A missing S3 object is a 404 in production only because the instance role holds `s3:ListBucket`.** Without it S3 answers an absent key with 403 AccessDenied, `S3Service` catches only `NoSuchKeyException`, and the read is a 500. MinIO's root credentials can always list, so no test sees the difference. Granted 2026-09-12 — do not trim it as unused; [`rules/aws-handling.md`](rules/aws-handling.md).
- **Elastic Beanstalk's nginx refuses request bodies over 1 MB by default**, under the 5 MB per-file cap, and local and CI have no nginx. Until `deploy/eb/.platform/nginx/conf.d/` ships (*Now* 1), a production upload over 1 MB is nginx's HTML 413, not Spring's.
- **MinIO is not on Docker Hub.** `docker pull minio/minio` is refused; the images are `quay.io/minio/minio` and `quay.io/minio/mc`, pinned alike in `docker-compose.yml` and `MinioTestContainer`.
- **`docker compose up -d` does not rebuild the backend image, and the image carries the jar.** The 2026-09-12 round trip first ran against a stale image still writing pre-BUG-039 filename keys. Use `--build`, or `compose watch`.
- **A deviation recorded as fixed is one nobody re-checks.** `DevDataSeeder` never ran for three weeks because a skill file credited a migration that does not exist ([BUG-041](bugs/fixed_bugs.md#bug-041)); [`rules/db-migrations.md`](rules/db-migrations.md).
- **A rule that does not load is a rule nobody reads.** `rules/backend-clubs.md` governed `clubadmin/` in its prose but not in its `paths`, so the `official_email` rule written on 2026-09-10 never once loaded for `ClubAdminService.java`. Fixed the same day. **Nothing in the repo would have caught it** — `check-docs` maps docs to code, not rules to the files they claim to govern. Check a rule's frontmatter actually covers what it talks about.
- **An accepted ADR's `Revisit when` is invisible at the moment it fires**, because ADRs are never auto-loaded. ADR-005's divergence trigger half-fired twice before anyone noticed. Triggers now live in `rules/contracts.md` (loads on both `*Request.java` records) and `rules/backend-clubs.md`; the reasoning stays in the ADR.
- **ADR-004 has taken two in-place amendments, and two is the ceiling.** A third means the record is being maintained rather than frozen, and the answer then is a superseding ADR ([`decisions/README.md`](docs/decisions/README.md)).
- **Bug ids have now collided three times.** Grep *both* `bugs.md` and `fixed_bugs.md` for the next free id before filing — `BUG-038` was issued to two different bugs, and so was `BUG-040`, whose open half became `BUG-051` on 2026-09-12. **Highest issued: BUG-051.**
- **A success callback belongs outside the `try` that wraps the write.** Navigation, a context refresh and `revalidateTag` all run after the write succeeded, so a throw there was caught by the write's own `catch` and the form claimed the club had not been created when it had ([BUG-045](bugs/fixed_bugs.md#bug-045)); [`rules/frontend.md`](rules/frontend.md).
- **Moving it out is only half of it — `await` it in a `catch` of its own.** These callbacks are async, so calling one without awaiting drops the promise: the club was created, the form had already blanked itself, and the user was told nothing ([BUG-047](bugs/fixed_bugs.md#bug-047)); [`rules/frontend.md`](rules/frontend.md).
- **A stale Turbopack dev bundle reports errors that contradict the file on disk** — a `Module not found` for a committed file, and a signature mismatch from a hook that had already changed, both while `tsc` and `npm run build` were clean. Restart `campusvibe-frontend` before debugging ([BUG-045](bugs/fixed_bugs.md#bug-045)); [`rules/frontend.md`](rules/frontend.md).
- **`clubs.social_links` is never written raw.** Both writers go through `ClubSocialLinks.normalise`, which validates and re-serialises, because two of those values reach an `href` on the public club page and were stored exactly as sent until 2026-09-10 ([BUG-048](bugs/fixed_bugs.md#bug-048)); [`rules/backend-clubs.md`](rules/backend-clubs.md).
- **A form that validates in JavaScript needs `noValidate` on the `<form>`.** Otherwise an invalid `type=email` or `type=url` makes the browser block submit entirely, so the validator never runs and its message is never written — the same trap `FormField` already dodges for `required` ([BUG-049](bugs/fixed_bugs.md#bug-049)); [`rules/frontend.md`](rules/frontend.md).
- Widening a signature leaves call sites and tests behind, and javac stops at the first phase so a `testCompile` break hides ([BUG-036](bugs/fixed_bugs.md#bug-036)); [`rules/backend-java.md`](rules/backend-java.md).
- **A green branch goes red when an advisory is published, not only when code changes** — three times now. The lever is a property override in `backend/pom.xml`, never a parent bump: `<tomcat.version>` ([BUG-035](bugs/fixed_bugs.md#bug-035), [ADR-003](docs/decisions/ADR-003-tomcat-pinned-beyond-the-boot-bom.md)) and `<netty.version>` ([BUG-050](bugs/fixed_bugs.md#bug-050), [ADR-008](docs/decisions/ADR-008-netty-pinned-beyond-the-boot-bom.md)). Dependabot maintains neither; [`rules/ci-and-build.md`](rules/ci-and-build.md).
- A migration already on `origin/develop` or `origin/main` is immutable — supersede it with the next `V` ([`rules/db-migrations.md`](rules/db-migrations.md)).
- **AWS calls are gated.** `scripts/hooks/guard-aws.mjs` allows reads and S3 writes and refuses everything else, on the CLI *and* the boto3 MCP path; a refusal is stop-and-ask, and `CAMPUSVIBE_ALLOW_AWS_WRITE=1` is the way through once Arpan approves ([`rules/aws-handling.md`](rules/aws-handling.md), [ADR-009](docs/decisions/ADR-009-aws-guardrails-enforced-by-a-hook.md)). **The bypass is read from the environment Claude Code was started in** — typed in front of a command it does nothing — so an approved write is simplest run by Arpan with `!`. Every `delete-*` is outside the S3 carve-out, `delete-bucket-cors` included.
- `aws-deployment.md` says no RDS, no S3 bucket and no EB exist. All three do, as of 2026-09-08 — do not trust that doc's state section until it is reconciled. Its S3 half now carries a dated pointer to ADR-012.
