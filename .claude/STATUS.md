## Watch out

- **`/planner` state lives in `PlannerProvider` in the planner layout, not in the pages.** A new chat's first message moves the URL to `/planner/{id}` while the reply streams; state kept in the page is dropped on that move. A streamed body goes through `apiFetchResponse`, never a bare `fetch` or `EventSource` ([`ai-planner.md`](docs/architecture/ai-planner.md)); [`rules/frontend.md`](rules/frontend.md).
- **The eight `ApiPlanner*` types are outside the DTO contract** until the planner backend adds them, so a rename on either side passes both suites; [`rules/contracts.md`](rules/contracts.md).
- `Club.id` is an assigned slug, so `save` merges and hands back a *different* instance — two bugs in one method ([BUG-034](bugs/fixed_bugs.md#bug-034), [BUG-037](bugs/fixed_bugs.md#bug-037)); held by [`rules/backend-clubs.md`](rules/backend-clubs.md), fix proposed in [ADR-002](docs/decisions/ADR-002-club-id-is-an-assigned-slug.md).
- Never accept Copilot Autofix on CodeQL alerts 14/15 — returning a copy of an entity collection loses every upload ([BUG-022](bugs/fixed_bugs.md#bug-022), [BUG-023](bugs/fixed_bugs.md#bug-023)); [`rules/backend-java.md`](rules/backend-java.md).
- **`ClubService.create` no longer exists** — `createOwnedBy` is the only way to make a club, and a null owner means born ownerless, which only the dev seeder may pass ([ADR-004](docs/decisions/ADR-004-two-paths-create-a-club.md)); [`rules/backend-clubs.md`](rules/backend-clubs.md).
- **A stored S3 key is not a URL, and `next/image` throws on one *during render*** — no `onError` can catch it, so one bad row takes a whole page down ([BUG-040](bugs/fixed_bugs.md#bug-040)); [`rules/frontend.md`](rules/frontend.md).
- **The store no longer guards the key, so the code must.** MinIO, like S3, reads `..` in a key as two characters; the filesystem stub that stood in for S3 until 2026-09-12 turned it into a file write, which was [BUG-039](bugs/fixed_bugs.md#bug-039). `MediaKeys.assertSafeKey`, applied in `S3Service`, is now the only check — do not remove it because the store does not need it ([ADR-011](docs/decisions/ADR-011-minio-replaces-fakes3.md)); [`rules/backend-java.md`](rules/backend-java.md).
- **Every Spring context needs `aws.s3.bucket`.** No default, and a blank value is rejected — so a test class that skips the `test` profile must name it, as `SearchIT` and `SearchRateLimitIT` now do, and an environment that forgets `AWS_S3_BUCKET` refuses to boot ([BUG-051](bugs/fixed_bugs.md#bug-051), [ADR-012](docs/decisions/ADR-012-one-media-bucket-with-prefixes.md)); [`rules/backend-java.md`](rules/backend-java.md), [`rules/aws-handling.md`](rules/aws-handling.md).
- **…and that includes `_database.yml`'s `migrate` job.** It boots the jar with no profile, the push loop skips it (`run-migrate: false`) and `verify.mjs` never boots, so a property that loses its default fails only on a pull request — PR #51, three days after `806a1d0` ([BUG-052](bugs/fixed_bugs.md#bug-052)); [`rules/ci-and-build.md`](rules/ci-and-build.md).
- **A missing S3 object is a 404 in production only because the instance role holds `s3:ListBucket`.** Without it S3 answers an absent key with 403 AccessDenied, `S3Service` catches only `NoSuchKeyException`, and the read is a 500. MinIO's root credentials can always list, so no test sees the difference. Granted 2026-09-12 — do not trim it as unused; [`rules/aws-handling.md`](rules/aws-handling.md).
- **Elastic Beanstalk's nginx refuses request bodies over 1 MB by default**, under the 5 MB per-file cap, and local and CI have no nginx. `deploy/eb/.platform/nginx/conf.d/` raises it to `10M` from 2026-09-12 — change it together with `max-request-size`; no test can prove it. **Proved in production 2026-09-15** by a 1.7 MB upload.
- **The EB bundle's zip entries must use forward slashes.** Windows PowerShell's `CreateFromDirectory` wrote `.platform\nginx\...`, which the instance unzips as one misnamed file: the deploy succeeds and the config does nothing. `package-eb.mjs` writes entries itself now; check `unzip -l` after touching it ([`rules/ci-and-build.md`](rules/ci-and-build.md)).
- **Serve every stored image through `s3/StoredImageResponses`**, clubs and events alike. Its raster-only content types and `nosniff` are the SVG guard; a second copy in a controller is the one that drifts (BUG-039, BUG-042); [`rules/backend-clubs.md`](rules/backend-clubs.md).
- **A media URL must change when its image does — through a path segment, never `?v=`.** URLs name a position, image responses are cached five minutes, and a reorder kept showing the old banner; `next/image` throws during render on a local `src` with a query string, so the first fix took every image page to 500 ([BUG-056](bugs/fixed_bugs.md#bug-056), [ADR-016](docs/decisions/ADR-016-media-urls-versioned-by-key-hash.md)); [`rules/frontend.md`](rules/frontend.md).
- **Never reach into a third-party widget’s DOM.** `GoogleAuthButton` found Google’s rendered button in our own page and called `.click()` on it; GIS switched to a cross-origin iframe, which nothing in a page can click into, and Google sign-in answered *not ready yet* while the script, the client id, the origin and the CSP were all fine. **That shape varies by context, not just by browser** — `localhost` and production rendered differently in the same Chrome at the same moment, which is why development never saw it ([BUG-057](bugs/fixed_bugs.md#bug-057), [ADR-018](docs/decisions/ADR-018-google-renders-and-styles-its-own-button.md)); [`rules/frontend.md`](rules/frontend.md).
- **An event's photo order is data: position 0 is the banner.** `sort_order` (V34) with `@OrderColumn`; reorder in place, and `(event_id, url)` stays unique only because the constraint is deferred to commit ([ADR-015](docs/decisions/ADR-015-event-banner-is-the-first-photo.md)); [`rules/backend-clubs.md`](rules/backend-clubs.md), [`rules/db-migrations.md`](rules/db-migrations.md).
- **Every DTO carrying an S3 key needs an adapter**, not only `ClubDTO`: the managed-club reads returned `logo` raw, and uploaded logos never showed in the dashboard ([BUG-055](bugs/fixed_bugs.md#bug-055)); [`rules/frontend.md`](rules/frontend.md).
- **A local database can hold a migration draft the repo never committed.** Arpan's compose database had run an earlier `V12` (*remove mock club seed data*) that was renamed before commit, so Flyway refused to start on a checksum mismatch and the schema had stopped at V12. **`flyway repair` is not the fix** — it adopts the new checksum without running the committed V12. Reset the volume. Reset 2026-09-13; [`rules/db-migrations.md`](rules/db-migrations.md).
- **MinIO is not on Docker Hub.** `docker pull minio/minio` is refused; the images are `quay.io/minio/minio` and `quay.io/minio/mc`, pinned alike in `docker-compose.yml` and `MinioTestContainer`.
- **`docker compose up -d` does not rebuild an image — backend or frontend.** The backend image carries the jar, and the 2026-09-12 round trip first ran against a stale one still writing pre-BUG-039 filename keys. On 2026-09-15 the frontend container served a build from the day before, so Arpan saw no Edit, Delete or photo upload in code that had them. Use `--build`, or `compose watch`, and check `docker images` before believing a feature is missing.
- **Docker shields the running backend, not the tests.** Testcontainers puts only Postgres in a container; the code under test runs in the host JVM, and this machine's formats numbers as `fr_CA`, which is what BUG-001 was. The test JVMs are pinned to en_US/UTC in `backend/pom.xml` and the runtime JVM in `backend/Dockerfile`, and numbers are bound into SQL, never formatted in ([BUG-001](bugs/bugs.md#bug-001)); [`rules/backend-java.md`](rules/backend-java.md), [`rules/ci-and-build.md`](rules/ci-and-build.md).
- **A deviation recorded as fixed is one nobody re-checks.** `DevDataSeeder` never ran for three weeks because a skill file credited a migration that does not exist ([BUG-041](bugs/fixed_bugs.md#bug-041)); [`rules/db-migrations.md`](rules/db-migrations.md).
- **A rule that does not load is a rule nobody reads.** `rules/backend-clubs.md` governed `clubadmin/` in its prose but not in its `paths`, so the `official_email` rule written on 2026-09-10 never once loaded for `ClubAdminService.java`. Fixed the same day. **Nothing in the repo would have caught it** — `check-docs` maps docs to code, not rules to the files they claim to govern. Check a rule's frontmatter actually covers what it talks about.
- **An accepted ADR's `Revisit when` is invisible at the moment it fires**, because ADRs are never auto-loaded. ADR-005's divergence trigger half-fired twice before anyone noticed. Triggers now live in `rules/contracts.md` (loads on both `*Request.java` records) and `rules/backend-clubs.md`; the reasoning stays in the ADR.
- **ADR-004 has taken two in-place amendments, and two is the ceiling.** A third means the record is being maintained rather than frozen, and the answer then is a superseding ADR ([`decisions/README.md`](docs/decisions/README.md)).
- **Bug ids have now collided three times.** Grep *both* `bugs.md` and `fixed_bugs.md` for the next free id before filing — `BUG-038` was issued to two different bugs, and so was `BUG-040`, whose open half became `BUG-051` on 2026-09-12. **Highest issued: BUG-057.**
- **A success callback belongs outside the `try` that wraps the write.** Navigation, a context refresh and `revalidateTag` all run after the write succeeded, so a throw there was caught by the write's own `catch` and the form claimed the club had not been created when it had ([BUG-045](bugs/fixed_bugs.md#bug-045)); [`rules/frontend.md`](rules/frontend.md).
- **Moving it out is only half of it — `await` it in a `catch` of its own.** These callbacks are async, so calling one without awaiting drops the promise: the club was created, the form had already blanked itself, and the user was told nothing ([BUG-047](bugs/fixed_bugs.md#bug-047)); [`rules/frontend.md`](rules/frontend.md).
- **A stale Turbopack dev bundle reports errors that contradict the file on disk** — a `Module not found` for a committed file, and a signature mismatch from a hook that had already changed, both while `tsc` and `npm run build` were clean. Restart `campusvibe-frontend` before debugging ([BUG-045](bugs/fixed_bugs.md#bug-045)); [`rules/frontend.md`](rules/frontend.md).
- **`clubs.social_links` is never written raw.** Both writers go through `ClubSocialLinks.normalise`, which validates and re-serialises, because two of those values reach an `href` on the public club page and were stored exactly as sent until 2026-09-10 ([BUG-048](bugs/fixed_bugs.md#bug-048)); [`rules/backend-clubs.md`](rules/backend-clubs.md).
- **A form that validates in JavaScript needs `noValidate` on the `<form>`.** Otherwise an invalid `type=email` or `type=url` makes the browser block submit entirely, so the validator never runs and its message is never written — the same trap `FormField` already dodges for `required` ([BUG-049](bugs/fixed_bugs.md#bug-049)); [`rules/frontend.md`](rules/frontend.md).
- Widening a signature leaves call sites and tests behind, and javac stops at the first phase so a `testCompile` break hides ([BUG-036](bugs/fixed_bugs.md#bug-036)); [`rules/backend-java.md`](rules/backend-java.md).
- **A green branch goes red when an advisory is published, not only when code changes** — three times now. The lever is a property override in `backend/pom.xml`, never a parent bump: `<tomcat.version>` ([BUG-035](bugs/fixed_bugs.md#bug-035), [ADR-003](docs/decisions/ADR-003-tomcat-pinned-beyond-the-boot-bom.md)) and `<netty.version>` ([BUG-050](bugs/fixed_bugs.md#bug-050), [ADR-008](docs/decisions/ADR-008-netty-pinned-beyond-the-boot-bom.md)). Dependabot maintains neither; [`rules/ci-and-build.md`](rules/ci-and-build.md).
- A migration already on `origin/develop` or `origin/main` is immutable — supersede it with the next `V` ([`rules/db-migrations.md`](rules/db-migrations.md)).
- **AWS calls are gated.** `scripts/hooks/guard-aws.mjs` allows reads and S3 writes and refuses everything else, on the CLI *and* the boto3 MCP path; a refusal is stop-and-ask, and `CAMPUSVIBE_ALLOW_AWS_WRITE=1` is the way through once Arpan approves ([`rules/aws-handling.md`](rules/aws-handling.md), [ADR-009](docs/decisions/ADR-009-aws-guardrails-enforced-by-a-hook.md)). **The bypass is read from the environment Claude Code was started in** — typed in front of a command it does nothing — so an approved write is simplest run by Arpan with `!`. Every `delete-*` is outside the S3 carve-out, `delete-bucket-cors` included.
- **A load-balanced environment answering 503 with a clean container log is a zone problem until proved otherwise.** Read `elbv2 describe-target-health` before the application: `Target.NotInUse` means the instance is in a zone the load balancer does not serve. A change that recreates the Auto Scaling group — `MaxSize` did — can move the instance to any subnet the group lists ([BUG-054](bugs/fixed_bugs.md#bug-054)); [`rules/aws-handling.md`](rules/aws-handling.md).
- **The two *idle* Elastic IPs are the load balancer's.** `3.96.239.88` and `15.175.46.76` are what the environment CNAME resolves to. The old cleanup item said release them; it is withdrawn.
- **The container log is read with `aws logs get-log-events`**, stream named by instance id. The guard hook refuses `aws logs tail` as a non-read.
- **`NEXT_PUBLIC_*` on Vercel take effect only on the next build**, and so does the CSP's `connect-src`, built from the same value. Change the API address and forget the redeploy, and the live site keeps calling the old one ([BUG-004](bugs/bugs.md#bug-004)).
- **`aws-deployment.md`'s body still describes the 2026-08-18 plan** — single instance, Cloudflare, PostgreSQL 15. Its dated sections at the top are current, the first deploy included; the body is not rewritten.
